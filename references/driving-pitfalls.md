# 自驾 · 实测踩坑清单（35 条，按需查）

> 只在自驾分支出问题时读（路由异动 / 绕行代价异常 / 充电点定位失败 / 静态图渲染不对）。正文口径见 `references/driving-route-planning.md`。

## 9. 实测踩坑清单（35 条，来自维护期实测）


| # | 坑 | 规则 |
|---|---|---|
| 1 | 自钉途经点"重塑走廊" → 白多 130 km / 4 h | 主线用地图**最快线**（§3） |
| 2 | 只给 1 个中途点 → 算路"到点折返"（画成来回） | **每 10–20 km 加密途经点**（§6.1） |
| 3 | 途经点按地名二次查询 → 撞同名村（示例村偏 30 km） | **取"落在走廊线上"的搜索结果**（§6.1） |
| 4 | 锚点原坐标直接标 → 离线最多 9.5 km | **先投影到路线折线**（§8） |
| 5 | 出 / 入点投影到**主线** → 点飘到绕行线中段 | **取出绕行线折线的首 / 末点**（§6.1） |
| 6 | 裸地名撞同名村（`示例枢纽` → 示例县的村） | 先用**高速要素**（收费站 / 互通 / 服务区）定位；裸地名标"待确认"（§5） |
| 7 | 平行高速**假压线**（G70 福银 / G55 二广） | **锚点自带路名必须与记录路名一致**（§5） |
| 8 | 跨段记录取"两端中点" → 假压线 | **两个锚点各自投影，取离主线最近的那个**（§5） |
| 9 | 邻省同名地点（福建记录落到广西） | 用记录自带的 **`scope` 做省别校验**（§5） |
| 10 | 把"地图推荐线"当"避堵线" | **推荐线不构成避堵结论**；要按 §5 逐条取证 |
| 11 | 以为能查"未来某天堵不堵" | **未来出行接口无权限**（10002 / 10017）→ 只能靠官方公告（§4） |
| 12 | 直接 `--screenshot` 抓图 → 白板 | **走 CDP、等渲染完、隐藏登录浮层**（§8） |
| 13 | 同一张图的耗时前后不一致（16h27m ↔ 17h9m） | **以当次截图为准**；口径细则见第 24 条（§8） |
| 14 | 红线越过入点、标签互相压住 | **拥堵段用红点＋水平引线（不画红线、不建图例）**；引线只连自己那个点、标签走 `parallel:true` 阶梯排布，出／入用两个 `type:"point"` 标出（§8） |
| 15 | 结论库没记录就以为"不堵" | 只能写「**未发现被点名路段**」；**库没记录 ≠ 不堵**（§5） |
| 16 | 生成了还想改 → 被"重生成上限"挡住 | **单独一条命令**跑 `node scripts/make_html.js --reset-runs <out.html>`（不接数据文件）复位后重出，见 `scripts-reference.md` |
| 17 | **硬造绕行线**：出口→中转点→拐回原高速入口，看着像"绕行"其实是**多跑 30 km 还穿堵段** | **逐段指令验不折返 + 反向连通性检查**；不可行就**老实写"不绕"**（§6.1） |
| 18 | **以为官方分流一定能复现** | 官方通告可能依赖**临时匝道 / 现场组织**；要用当前路网实测一遍（实测示例互通A互通进口侧不连通）（§6.1） |
| 19 | 手钉途经点"换更远的口上高速"看着只多几十公里 → 其实在县道上**折返**、最后**仍回到原高速穿堵段**（假绕行） | **按整条线比选 + 逐段指令验不折返**：实测「绕示例互通A」多约 30 km 却仍跑 G80 23.7 km；真正可行的是「不走高速」自己算出的 **示例互通B 52.2 km 纯地面**（§6.1 A1/A2、B4） |
| 20 | 拿"主线切片里程"当绕行代价的基线 → 省不省算反 | **代价必须与地图面板同源**：同一组起终点各算一次「默认高速」与「不走高速」（实测 G45 丁城段：直走高速 55.1 km／38 min，地面绕行 57.1 km／68 min ⇒ **该段高速得多花半小时才值得改走**；同日实时还会在 37–41 min 之间浮动）（§6.1 A1/B） |
| 21 | 几十公里不换路的**长 step 跨过查询点** → 本线取不到路名 → 真节点被当"平行线"剔掉（G45 丁城段 2026 + 2024 两次点名，却整条消失） | `congestion-nodes.js` 取路名改成**按 step 覆盖区间**（`起点里程 = s.km − s.dist`，±30 km 窗口），窗口空则退回里程最近的 3 个 step；**取不到路名时不判平行线、交人工复核**（§5） |
| 22 | 内嵌地图截图后，**三项宽度实测整段 SKIP**（只写"浏览器调用失败"） | 溢出量测要读回整页 DOM（内嵌截图后可达数 MB），**必须带 `maxBuffer`**（`check_html.js` 已内置 256 MB）；否则 `ENOBUFS` 会被误当浏览器坏了（§8、SKILL.md「HTML 出品校验」） |
| 23 | 截图里 **2–3 条备选路线全画出来**（左侧还列 3 张卡片）→ 图上"很混乱"（客户直接打回） | 出图加 **`--single`**（要哪条先 `--pick N`）；**认线看颜色不按点数**（§8） |
| 24 | 讲解页写"直走高速 29 min"、截图面板却显示 26 min → 看着像对不上 | 耗时是**查路时读数、实时会浮动**：图例与 note 都标"查路时读数"，结论**只讲阈值**、不承诺绝对分钟数（§8） |
| 25 | **URL 上写 `policy=3`（不走高速）以为就绕开高速了** → 网页版照样给全程高速 | 网页版**只有点开「偏好」选「不走高速」才生效**（出图用 `--pref 不走高速`）；已实测 `policy=3` 与 policy=0 返回同一条高速线（§6.1 A1、§8） |
| 26 | **同一条链接的默认路线会随实时路况漂** → 图上面板里程与报告不符、红线脱离绿线 | 客户已指示「默认地图最快线」→ **不钉途经点**：**先出图、按图上这条线做分析**，一个交付内所有数字取**同一次查路读数**，图例／页面写明「规划时读数、实时会浮动」。**只有客户指定走廊时才钉 1 个** `vias`（钉 1 个够、钉 2 个是浪费；0 个曾给 G4 京港澳 2118.8 km／¥1055、2026-10-17 给 G45 大广 约 2119 km／¥1055；1 个「辛城」与 2 个「吉安+辛城」折线逐点一致 n=17629）（§8 ⑥） |
| 27 | **图例/标签压在路线上** → 客户："注释挡住路线图了" | 标注摆放要**按路线几何打分避让**（压线权重最高）、**图例四角择优**、图例尽量小；交付前**裁图放大看一遍**（§8） |
| 28 | **充电桩点落进被点名拥堵段**（实测：甲城→乙城第 1 站原本选**丁城服务区 267 km**，而丁城段被点名区间是 **234.8—288.6 km**——不但堵，绕行时还够不着它） | 定桩点前把里程逐个塞进 §5 的 HIT 段区间做 `∈` 判断；被套住的换成**绕行出口之前 / 之后**的服务区（本例改**示例服务区A服务区 231 km**，绕行出口就在 234.8 km 的示例服务区A收费站）；并**把充电点画到总览图上、菜单写明间隔**（§7.1、§8 ⑦） |
| 29 | **图上「点—名字」没有引线或标签飞出去几百上千像素**（客户 2026-10-16 打回，2026-10-17 又给了新口径） | 定稿：**拥堵段＝红点＋水平引线引出段名、充电点＝蓝点＋水平引线引出服务区名、总览图不出菜单/表格**；`parallel:true` 时同侧按 y 排阶梯、只走水平引线；**四数全 0** 才算过 |
| 30 | **换了走廊 / 重算了点，却仍用旧 `_u_*.txt` 里的链接出图** → 标注投到**旧路线**上（实测：菜单写着"己城段"、底图却是庚城—辛城，两个标签飞到 1500 px 外、菜单与标签互压） | **换走廊后必须重跑 `map-shot.js link`**（`_u_*.txt` 只是缓存）；出图后先看 `标注退让` 是否为 0，再裁图放大复核（§8） |
| 31 | **把底图自带的 POI 小图标当成"我们的标注"**（客户 2026-10-17 直接问："你为什么总览图里有一个黄点"） | 高德底图的设施图标（服务区 / 加油站等）画在 **map 的 canvas** 上（`--js` 探过：该点命中的只有 `CANVAS.amap-layer`，`.amap-marker` 只有路线起终点 3 个），**DOM 删不掉**，还会压在我们画的绿线上。对策：① 我方标注只用**固定色**（充电点 `#0B72C4` 蓝点、拥堵段 `#C62828` 红点），与底图图标（金色圆点）明显区分；② **菜单（节点图）／图注（总览图）必须声明**"底图上金色／彩色小圆点＝高德自带的设施图标，不是本报告的标注"（`map-shot.js` 已内置）；③ 客户问起就按此解释、**不要改图**（§8） |
| 32 | **用 `AMap.CircleMarker` 画的点被高德地名层压住**（实测：示例收费站A／丁城／戊城／己城／乙城的红点几乎全被「丙城」「乙城」等文字盖掉，图上像没画） | 点改用 **DOM `AMap.Marker`**（content 里放带白边的圆 div，zIndex 高于矢量层）；`map-shot.js` 已内置 |
| 33 | **讲解页还按老结构排「逐段细则页」**（每处拥堵一页、每页一张地图）→ 客户 2026-10-17 明确「删除每个拥堵路段的细则页」，只要两件事：总览图讲位置、第③段讲依据与「从哪个口下／哪个口上」 | 页面固定五段：① 总览图（点＋引线＋名字，无菜单无表）② 电车充电清单（只放充电，拥堵上下口不进来）③ 拥堵解读表（拥堵路段（节点）／依据／下高速口／上高速口／预案，5 列）④ 说明（严重度、未获取项、当天复核清单）⑤ 来源；`make_html.js drive --check` 会校验 `waypoints ≥ 2 行`、表头含「依据」「预案」、notes 含「未获取」「复核」「严重度」、禁用「已避开拥堵／全程无堵／保证不堵／零拥堵」 |
| 34 | **讲解页第 2 页把「充电服务区」和「拥堵下/上高速口」混在一张表**（客户 2026-10-17：「拥堵路段和充电服务区分开，第二页混在一起太乱」） | 第②段＝**纯电车充电清单**（累计里程／服务区／本段里程／桩品牌·实测距离／备注）；拥堵的「下口/上口/预案」只在第③段解读表；`make_html.js drive --check` 会拦 waypoints 里出现 收费站 / 下高速 / 上高速 / 互通 / 匝道 |
| 35 | **车辆类型＝油车，却给了服务区／充电推荐**（客户 2026-10-17：「如果不是电车可没有服务区推荐哦」） | 油车：**不规划充电点、总览图不画蓝点、讲解页不设充电清单段、不推荐任何服务区**；只做避堵路线。`vehicle` 写「油车」时 `make_html.js drive --check` 会拦 charging 字样与充电清单 |
