# 景点预研子代理 · 自包含任务书

> **这份文件是派给子代理时让它自己读的**（主流程不要整篇读）。它包含：任务、产出、字段结构与完整 JSON 示例、质量红线、门禁、景点基线与检索预算、步骤 1～4 要点。
> 子代理**看不到主对话**，也**不要让它读 `SKILL.md` 或任何脚本源码**。

## 任务与产出


> **怎么用**：派发那一刻，把下面「prompt 必须自包含四项」照着写全，并**把「步骤 1～4 要点」「数据 JSON 完整示例」「结构硬性要求」「检索预算」这四段整段抄进 prompt**。
> **不要抄给子代理**：上半部分的分工纪律、以及本节的门禁/基线说明里"主流程该怎么做"的部分——那是给你的。
> 子代理**看不到本次对话**，也**不要让它去读 `SKILL.md`**（两万多字符，读一遍就白烧两万多 token）。

- **prompt 必须自包含**（子代理看不到本次对话），至少写清四项：
  1. **目的地**；并**把「步骤 1～4 要点」直接抄进 prompt**——**不要再让子代理去读 `SKILL.md`**：正文两万多字符，**整读一遍就是两万多 token**，而它真正需要的只有这几条（实测这么干白烧约 16k token + 一次往返）。
  2. **产出文件**：工作区根目录下的 **`<目的地>景点数据.json`**，**只准写这一个文件**、不动工作区其他内容；
  3. **字段结构** = `make_html.js spots` 的 `spots[]`（`name` / `meta` / `urlLabel` + `url` / `good[0~2]` / `bad[0~2]` / `mine` / `source`，可选 `ticket` / `urlFallback`）+ 顶层 `coverTitle` / `coverSubtitle` / `coverCards` / `coverNote` 与 `overview.rows` / `colWidths`（数字权重，见「make_html.js 用法」）；`meta` 写"类型 · 时长 · 开放时间/闭馆日 · 距目的地 · 热门（或不热门）"；`ticket` 只回答"要不要买票"（`paid` / `free` / `free_with_fee_parts`，后者用 `parts` 列园中园/索道等收费子景点）——**不写票价**，客户口径是只算车费；
      - **把下面的完整示例整段抄进 prompt**——子代理照着它产出的 JSON 一次就能过生成器校验，**不必去读 `make_html.js` 源码**（技能明文禁止读源码；实测子代理为了猜字段结构读了两遍 34 KB 源码，纯浪费）。
  4. **质量红线**：数量与热门/不热门配比达标、**`coverCards` 等的数字必须与 `overview` 的实际热度统计一致**（不得出现"热门 2"而总览列了 3 个热门）、**网址合规**（两种合格形态与禁止清单见步骤 3；**生成器按形状硬性校验，不合格直接拒绝生成**）、评语**不得虚构数字或原话**、查不到就如实写"以景区公示为准"。
  5. **产出后必须跑门禁，必须 exit 0**（**硬性**）：
     ```
     node scripts/spots_check.js <你的产出文件>
     ```
     - **PASS（exit 0）才算完**。FAIL 就按它逐条列出的问题**自己改数据**，改完**重跑**。
     - **最多改 2 轮**；2 轮还过不了，就把**当前数据 + spots_check 的完整输出**一起交回来（并说明卡在哪条），**不要无限重试**。
     - 这条的意义：这些规则**原本只有生成 HTML 时才会检查**，那时你已经结束、主流程要跨进程返工。**这里过一次，等于把返工消在你自己上下文里。**
     - 常见退件原因（先自查，省一轮）：
       - **B5**：每个景点的 `meta` **必须**含开放时间（形如 `08:30-17:30` 或"全天"），**或**显式写"以景区公示为准"——二者必居其一，不许留空、不许只写"详见官网"。
       - **B1/B2**：5～10 个；`meta` 里要能数出 **≥2 个热门**与 **≥2 个不热门**。
       - **B7**：`coverCards` 里「热门景点 / 不热门景点 / 推荐景点」三张卡的**值必须与 `spots[].meta` 实际统计一致**（别改完 meta 忘了改封面卡）。
       - **B3**：网址只能是①该景点官网、②马蜂窝/去哪儿/欣欣上该景点的**详情页**；政府信息公开·政务目录页 / 政务稿页 / 新闻稿 / 频道首页 / 携程系 / 短链 / 纯 IP 一律拒；**当地文旅局 / 管委会 / 省政府的「概况·介绍」文章页是合格的**。
     - **把 spots_check 的输出那一行（`spots_check: N PASS / 0 FAIL`）贴进你的返回消息**——主流程看这一行就知道过没过。
  6. **若 prompt 里附了「景点基线」（ChinaTravel，10 城），按下面三条用它**——**它是加速器，不是依据**：
     - **可以用它做**：① 生成候选池（名称/类型/开放时间/门票/建议时长，免去逐个检索）；② 初筛与排序。
     - **不可以**：把它的开放时间**直接当最终结论**——它是**常规时段口径**，旺季/节假日会调整，且**不含闭馆日**。
       **选入最终名单的景点，开放时间与闭馆日仍要按景区官网最近 1～3 个月的公告核对**；查不到就如实写"以景区公示为准"。
     - **建议游览时长口径偏保守，只作排序参考**：实测该数据集给「故宫博物院」`0.5–1h`，而常规攻略为 3～4h。
       **写入方案前对照攻略修正**，不要照抄。
     - **它没有官网字段**（`attractions` 表无 url 列）——**官网仍需 web_search 查**，并按步骤 3 的形状闸门校验。
     - **它没有航班与铁路数据可用**（同批 `flights`/`trains` 表已知有错）——**与本预研无关，但别去用它查任何时刻／票价**。
     - **碰不到基线时**（prompt 里没附）→ 一切照旧，全走 web_search。
   7. **检索预算（硬上限；实测超支过一次，这一项是本次会话最大的单笔开销）**：
      - **全程 `web_search` ≤ 12 次、`web_fetch` ≤ 8 次**。到上限就用已有信息产出，**未核到的如实写"以景区公示为准"**，不许为凑齐而超额检索。
      - **只抓"具体信息页"**：门票政策 / 开放时间公告 / 该景点详情页。**禁止抓官网首页与导航页**——实测抓了 40KB 的黄鹤楼首页、56KB 的辛亥革命博物院首页，信息密度极低，正文几乎全进了上下文。
      - **单页正文超过约 20KB 就不要再整页抓**：改用 `web_search` 摘要，或只抓那个具体子页（如"门票政策"页）。
      - **先把 6 个景点名单定下来，再只给入选景点找网址**——实测为两个最终落选的景点（晴川阁、古德寺）反复找合规详情页，烧掉约 1/4 的检索量。
      - **同一件事最多查 2 次**：同一景点的开放时间不超过 2 次检索，节假日专项每景点 1 次。实测湖北省博的国庆安排查了 3 轮、武汉植物园开放时间用了 8 条 query。
      - **禁止读脚本源码**（`spots_check.js` / `lib/validate.js` / `make_html.js` 都不要读）：用法跑 `--help`，字段照下面示例。实测读源码白烧约 20KB 上下文。
      - **依据（2026-09-26 第二轮 A/B 实测）**：该子代理跑了 **15 次 `web_search`（52 条 query）+ 26 次 `web_fetch`**，**其中 9 次抓取无效**（202/403/空页/跨域），是整场会话**单项最大的开销**（¥0.62，约占 1/3）；它自评"其中 3～5 次明确可省"。对照：第一轮同一子代理只花 ¥0.28。

## 步骤 1～4 要点（抄进 prompt，代替"去读 SKILL.md"）

1. **搜集**：用 `web_search` 到景区官方旅游网站 / 当地文旅局公示 / 马蜂窝 / 去哪儿 取景点信息；**优先目的地本身的景点**，凑不齐 5 个再按就近原则扩到同城或周边（标注"距目的地约 X"）。
2. **筛选**：最终 **5～10 个**，**至少 2 个热门**、**保底 2 个不热门**；每个标注类型 / 预估游览时长 / **开放时间与闭馆日** / 距目的地或到达站的远近与到达方式。
   - **开放时间与闭馆日必须按该景点官网最近 1～3 个月的公告核对**——节假日/旺季常临时调整（取消周一闭馆、延时、临时闭馆）；**不得默认"博物馆周一闭馆"**；山岳类另注意索道 / 观光车末班时间。查不到就写"以景区公示为准"。
3. **景区介绍网址（只给一条，且必须过评审）**：
   - **只给一个网址**：景区介绍页——首选**当地文旅局 / 景区管委会 / 景区官网的「概况 · 简介 · 景区介绍」页**（要点式：面积、等级、历史、主要景点；最好带图）。**不要给多个链接**，客户不会逐个点。
   - **评审机制（硬性，不许自评）**：候选 URL 先跑
     `node scripts/spot_link.js resolve --name "<景区名>" --url <候选1> --url <候选2> --cache`
     脚本抓页面、算要点/图文比、剔反爬页，并把评审结果写进 `data/spots-links.json`。
     - `grade=A`（要点 ≥10 且有图 ≥3）或 `grade=B`（要点 ≥5，图少）→ 把 `SPOT_LINK` 的 `intro` 填进 `url`；
     - `grade=F`（没有合格介绍页）→ **url 留空**，写 `urlFallback: "以景区公示为准"`，`urlLabel` 写"暂无官方介绍页"；
     - `spots_check.js` 的 **B8** 会核对：url 必须与缓存里 A/B 级的 `intro` 完全一致、评审 ≤90 天；F 级必须留空且写降级文案。**"我觉得这个网址不错"过不了 B8**。
   - 形状闸门仍生效（`scripts/lib/validate.js`）：短链 / 纯 IP / 携程系（trip.com、ctrip.com）/ 政府信息公开页（xxgk、zwgk 等目录）/ 频道栏目首页 / 政务稿页（仅 `*.gov.cn` 的 `/t日期_编号.html`）一律拒绝；**文旅局、管委会、省政府的「概况/介绍」文章页是合格的**。
   - **不要逐个 fetch 验证**：交给 `spot_link.js` 一次跑完（脚本只读页面头部 160KB，不进上下文）。
4. **写评语**：好评 / 差评**各最多 2 条**（公开评论确实少时允许只写 1 条甚至 0 条，缺的那栏整栏不渲染）；`mine`（我的点评）**至少 1 条、合计 ≥24 字**、尽可能展示积极面，**语气要像人在跟你说话**（可以幽默、可以有画面感、可以吐槽一两句，别端着写导游词；不得编事实、不得堆形容词）；`source`（来源标注）**必填**——写"来源：马蜂窝 / 去哪儿 / 大众点评 游客高频评价归纳"。**不得虚构数字或原话**；评论很少就如实写"公开评论较少，以上为综合攻略信息归纳"。


## 数据 JSON 完整示例（照它产出，一次就能过生成器校验）


```json
{
  "coverTitle": "<目的地>景点推荐",
  "coverSubtitle": "5 个精选 · 含 3 个热门 / 2 个不热门",
  "coverCards": [
    ["推荐景点", "5 个", "含 3 个热门、2 个不热门，覆盖自然 · 人文 · 古镇"],
    ["热门景点", "3 个", "甲景区 / 乙古城 / 丙雪山"],
    ["不热门景点", "2 个", "丁壁画 / 戊公园"],
    ["开放时间核对", "2026 年 9 月", "已逐个核对最近公告的开放时间与闭馆日"]
  ],
  "coverNote": "里程与票价为参考约数，出行前请以官方当日公示为准。",
  "overview": {
    "title": "景点总览",
    "rows": [
      ["甲景区", "自然 · 5h · 08:00-17:00 · 距市区 20km", "热门"],
      ["乙古城", "人文 · 3h · 全天 · 距市区 1km", "热门"]
    ],
    "colWidths": [40, 42, 18],
    "footnotes": ["闭馆日与开放时间均为最近公告口径，以景区公示为准。"]
  },
  "spots": [
    {
      "name": "甲景区",
      "meta": "自然 · 5h · 08:00-17:00 无闭馆日 · 距市区 20km · 热门",
      "urlLabel": "甲景区官网",
      "url": "https://www.example.com/",
      "good": ["景色层次丰富，索道运力足", "官方预约制后排队明显变短"],
      "bad": ["下午常起雾，观景看运气", "山上门票与交通分开收费"],
      "mine": ["建议赶早班索道，午后云量上来视野会差"],
      "source": "甲景区官网公告 + 旅游平台游客点评归纳"
    }
  ]
}
```

**结构硬性要求（照示例写，不要自创字段名）**
- `coverCards` 每张必须是**三元数组** `["标签", "值", "说明"]` 或三元对象 `{label,value,desc}`——**三项都要有内容，缺一项会被生成器拒绝**（"有空白项"）。写成两项是实测最常见的退件原因。
- `overview.colWidths` 是**数字权重数组**，个数必须等于 `rows` 的列数；**不要写百分比字符串**。
- `spots[].good` / `bad` 各**最多 2 条**、`mine` **至少 1 条**、`source` **必填**；没有就如实少写，**不得编造**。
- `urlLabel` **尽量短**（如"甲景区官网"／"乙古城 · 马蜂窝详情页"）：它是数据驱动文本，越短越不容易在 A4 打印版式下挤压版面。
- `url` 只能是该景点官网、旅游平台（马蜂窝/去哪儿/欣欣）详情页，或**当地文旅局/管委会/省政府的「概况·介绍」文章页**；**生成器按形状硬性拒绝**政府信息公开·政务目录页 / 政务稿页 / 新闻稿 / 频道首页 / 携程系 / 短链 / 纯 IP。
- **让子代理自检（写进 prompt）**：要求它**自己 `JSON.parse` 实测 + 核对字段与数量**，并把**一行自检结论写进返回消息**（如"spots=5、热门 3 / 不热门 2、8 个字段零缺失、JSON.parse 通过"）。
