# 流程一：城际交通方案 → HTML

> 本文件由 `SKILL.md` 指向。**进入流程一时必读**（在开始整理方案数据之前）。
> 口径以 `SKILL.md` 正文的「方案生成」「席别规则」「输出格式要求」为准，本文件只讲**怎么做**。

### 流程一：城际交通方案 → HTML

- **触发时机**：三段方案（**最省钱 1 个 + 最快 1 个 + 额外方案 ≥2 个**，见「方案生成」）生成并自检通过后**自动**进入本流程（用户的确认就是下一步「出行方案选择框」里挑一个）；用户直接要求"出 HTML / 出文档 / 做成网页"时也触发。
- **输入**：最终方案数据——起终点、日期、时间窗口、**客户要求的到达日**、人数、各方案明细（含窗口命中、到达日是否满足、余票校验结果）。
- **处理步骤**（顺序执行，全部产出后再交付）：
  1. **整理方案为结构化数据**：按 `scripts/make_html.js` 的字段规范写一个数据 JSON——`coverTitle/coverSubtitle/coverCards/coverNote`（封面）+ `overview{title,subtitle,rows,colWidths,footnotes}`（决策速览表；`colWidths` 为**数字权重**，见「make_html.js 用法」；注脚三种写法 `footnotes` / `note` / `noteBox` 通用）+ `cheapest{title,subtitle,plans[单方案]}`（**最省钱，只放 1 个方案**；方案说明文字一律写进该方案的 `footnotes[]`）+ `fastest{title,subtitle,steps[{time,place,desc}],costTitle,costRows[[标签,值]],footnotes}`（最快）+ `extra{title,subtitle,plans[...]}`（**额外方案，除最省钱/最快之外的方案，≥2 个、每方案单独一块**）。
     - **`plans[]` 单方案字段**（cheapest / extra 共用）：`title`（方案名，如"空中方案 · 直飞"）、`subtitle`、`price`（如"**二等座 ¥250.0 / 人**""**经济舱 ¥600.0 / 人**"，**票种按「价格必须标明票种」**）、`badge`（关键限定，如"比高铁直达快 3 小时 42 分"）、`steps[{time,place,desc}]`（**逐段路线时间线；最后一步 = 到达站/落地机场，不要再写"进城/市区"**）、`costRows[[标签,值]]`（费用明细，末行写合计；**首行标签写"车次 + 席别 + 票价"（如"G2911 二等座"→"¥250.0"）**；**不含到达端市内接驳**）、`footnotes[]`。
     - **封面卡写法（实测最常被拒的一处）**：`coverCards` 每张必须是**三项都有内容**的数组，如 `[["推荐景点","7 个","含 4 个热门、3 个不热门"]]`；只写两项会被生成器拒绝（"有空白项"）。
     - **过夜标记**：需要过夜的方案，在 `badge`、对应 `steps[].desc`（如"宿福州一晚"）与 `footnotes` 里写出"过夜/住宿/一晚"字样（标红机制见「方案生成 → 所有方案通用」）。
     - **额外方案给不满 2 个时**：把原因写进 `overview.footnotes` 或对应块 `footnotes`（如"当日直达余票不足，无更多可选方案"），生成器会把含"余票不足 / 余票不够 / 票不够 / 无票 / 放弃 / 不推荐"等字样的注脚标红强调。
  2. **生成网页（用参数化生成器）**：
     - 命令：`node scripts/make_html.js plan <data.json> <out.html> --check`（**生成 → 校验一条命令走完**）
     - 输出命名：「`<起点>到<终点>交通方案.html`」（工作区根目录）
     - 页面骨架由生成器固定（封面 → 决策速览 → **最省钱 → 最快 → 额外方案**）；**不要为排版增删内容**。
     - **出行参数落点**：出行参数（日期 / 时间窗口 / 人数）并入**封面副标题**；**出行提示只写在聊天回复里**（提示清单见「输出格式要求」）。
     - **网页里的代号落点**：时间线每一段与**费用明细卡对应行**都要带代号（如"MF8165 机票""北京段 高铁 G964"）；**代号是否齐全、给不出怎么办，一律按「方案生成 → 所有方案通用」裁决**。
   3. **校验在上一条命令里完成**：`--check` 跑 `check_html.js`（必须 PASS）；
      **校验 FAIL 时脚本会拒产、并删掉那个未过校验的 HTML**——改数据后**重跑同一条命令**即可。
      **不要**再单独跑 `check_html.js`。
  4. **弹出「出行方案选择框」**（打开交通方案页的同时——此时只打开这一个页面；景点页应已生成好但**不打开**）：用 `ask_user_question` 弹出一个选择框，把**全部方案一个不漏地**作为选项列给用户，选项名统一为——「**最省钱方案（¥X / Xh）**」「**最快方案（¥X / Xh）**」「**额外方案一（¥X / Xh）**」「**额外方案二（…）**」…（可附方式与代号，如"额外方案一 · 空中方案直飞 MF8165"）。用户选定的方案即**后续流程二景点行程的到达方式**（到达站/到达时刻），据此安排景点顺序。
- **输出**：`.html`（**单文件 HTML，本流程唯一的交付物**，见「交付形态」），及用户选定的出行方案。**本流程只打开交通方案页**；**景点页按「生成时机」处理**——正常情形在弹本框之前就已经生成好；**预研尚未就绪时走兜底路径**（不等它，景点页改在客户选定后生成）。无论哪条路径，都**要等客户选定之后才打开**（见「流程二 → 生成时机 / 打开时机」）。
- **页面样式已全部固化进 `scripts/make_html.js`**（满宽 / 打印 A4 / 微软雅黑 / 同款排布——**都无需你操心，也不必写在方案里**）。你只需守三条：**① 不要手改产出 HTML 的样式**；**② 不要为排版增删内容**；**③ 页面不出现技术 / 数据源信息**（见「输出格式要求」）。确需新页面类型时，在生成器里加渲染函数。
