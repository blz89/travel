# 行程方案 · 自驾口径（完整）

> 本文件是 `travel` 技能的**参考资料**，由 `SKILL.md`「行程方案规则」指向。
> **只有客户选了自驾（或在目的地自驾）时才读它**；公共交通分支不需要。
> **城际路段（出发地 → 目的地）的避堵与电车充电规划另见 `references/driving-route-planning.md`**（由「是否需要进行自驾路线规划」那个框触发）——**本文件只管景区之间的移动**。

---

## 一、自驾（自己开车玩景区）——只给自驾方案（行车路线）+ 依据

- **最优方案（路程最短）**：目标是**行驶路程最短**（不追时间；「最快」在本技能专指耗时最短的地图最快线）。
  - **起点**：按「出发点选择框」——用户自己决定 → 以**用户输入的那个景点**为起点；从到达地出发 → **自驾**以**靠近目的地的高速路口**为参照（沿出发地→目的地主线最近的下道口），第一个景点取距其最近者（详见「通用要求」）。
  - **接续**：按「通用要求」的最近邻串联（自驾取**行驶距离**最近者）。
  - 输出标注：每段里程、预计车程；并说明"这是行驶路程最短的串联顺序"。
- **错峰方案（避开景区人流高峰，可选）**：**错峰指的是避开"景区人流"高峰，不是避开交通高峰**（与早晚高峰、路况无关）。
  - **触发前提（决定是否考虑错峰）**：该景区**非常热门**且**有记录人流极大/拥挤的真实情况**（如节假日排队长、官方限流、游客爆满新闻等）才考虑错峰；**有些地区即便是热门景点也不会出现拥挤**，若没有拥堵记录则**不给错峰**、只给最快方案。
  - **可行性前提（决定路线能否串联）**：所选景点的**相邻两景区之间间隔 ≤ 20km**（串成一条线的相邻两点都 ≤20km 才可行），否则错峰方案不成立（仍按「最优方案（路程最短）」出一份）。
  - 两个前提都满足 → 给出错峰：把热门大客流景区排到**客流低谷时段**（开门即到 / 临近闭园前），或先玩冷门再玩热门；同样按最近邻串联，并说明"为什么这样排（基于该景区人流大的记录）"。
  - 任一前提不满足 → **只给最优方案（行驶路程最短）**，并说明原因（无拥堵记录 / 间隔超 20km）。

## 工程注记（2026-09-25）

- 本节的「最近邻串联」是**确定性算法**：给定所选景点的两两距离，顺序唯一确定。
  交给 `scripts/itinerary.js` 算（派生输入 = 距离矩阵），不要靠模型在文字里排。
- 错峰的**可行性前提**「相邻两景区间隔 ≤ 20km」也是可判定的数值条件，由同一个脚本校验。
