# 脚本用法速查（流程一 / 流程二 / 自驾出图，按需读）

> 本文件由 `SKILL.md` 指向。**只在需要调用脚本时读**，不要常驻。

## 12306.js 用法（**完整用法跑 `node scripts/12306.js --help`；不要读源码**）

```
node scripts/12306.js stations <关键词>                     # 搜车站（中文/拼音/简拼/三字码）
node scripts/12306.js tickets <出发> <到达> [日期] [--brief] [--from/--to HH:MM] [--out <文件>]   # 查全部车次（核心）
node scripts/12306.js transfer <出发> <到达> [日期]          # 官方中转（**只取第一页**）
```

- **日常只用 `tickets ... --brief`**：每车次一行，含全部席别的票价与余票。`--out <文件>` 落盘就用它自带的选项（**别用 PowerShell 的 `>` 重定向，会变 UTF-16**）。
- **无直达（或直达无票）时，`transfer` 是发现中转的首选路径，先跑它**；但它**只取第一页、给得很少**，返回 0 条或只有 1 条**都不代表**没有别的中转——**必须自己枚举沿途枢纽逐腿拼**。**枚举这件事用一条命令做完，不要逐条打字指挥**：
  ```
  node scripts/plan.js explore --chain "出发站,枢纽1,枢纽2,…,目的地站" [--chain "另一条链"] \
    --date <日期> [--pax N] [--from HH:MM --to HH:MM] [--arrive-by <到达日>] \
    --route "<起点>→<终点>" --out-dir <目录> --emit-data <目录>/data.json
  ```
  **你只给"哪几个枢纽值得试"（这是判断，仍归你）；逐腿查询 → 拼链 → 合并去重 → 换乘校验 → 三段归位 → 写出 `data.json` 全部由代码完成。**
  - **为什么必须用它**：一条链要跑 6～8 次调用（每条腿一次 `tickets`、再加 compose / candidates / rank / emit-data），**从前这些都得你逐条打字指挥**——实测一次运行 80+ 次调用，大头就是这个。现在**一次调用拿到短名单**。
  - **`--emit-data` 是关键**：它把 `make_html` 要的 `data.json` **由代码写出来**（价格、总耗时、到达时刻、逐段 `steps`、`costRows`、总览表全是代码算的）。**你只需补 `coverNote` 与各处 `footnotes` 的文案，不要改任何数字**，然后直接 `make_html.js plan <data.json> <out.html> --check`。
    **为什么**：手写十几 KB 的 `data.json` 曾是"两份成品把总价写错"的直接原因（席别改了、明细改了，总价却留着旧值）。**它不额外增加往返**——就在 rank 这一次调用里完成。
  - **枚举枢纽的纪律不变**：走廊上挑 **2～4 个顺路大节点**（如 甲市→乙市 取沿途两个顺路大枢纽），**只挑顺路的**；候选上限见下条。
  - **`explore` 失败会如实点名是哪条链、哪条腿失败**并提示换枢纽或换日期——**不得据此判"不可达"**。
  - **`plan.js compose`（跨腿拼链）**：若你要手工控制腿文件（如含跨市地铁/城际/大巴等非铁路腿），按 brief 格式手写腿文件后跑 `compose 腿1.txt 腿2.txt …`。完整格式跑 `node scripts/plan.js --help`。
  - **手写 `options.json` 的最小模板（照抄改数即可，别自己发明结构）**——实测"候选装配 4 轮返工"全部出自下面这四条：
    ```json
    [
      {
        "name": "高铁 G1523 直达（二等座）",
        "kind": "铁路",
        "windowHit": "窗口外",
        "extraCost": 0,
        "legs": [
          { "code": "地铁2号线", "from": "家", "dep": "2026-10-01 07:10", "to": "上海虹桥", "arr": "2026-10-01 07:48", "cost": 5, "seat": "地铁" },
          { "code": "G1523", "from": "上海虹桥", "dep": "2026-10-01 16:00", "to": "武汉", "arr": "2026-10-01 22:55", "cost": 615.5, "seat": "二等座" }
        ]
      }
    ]
    ```
    **四条硬规则（照做就不会返工）**：
    1. **腿按时间先后排**：接驳腿在最前、被接驳的车次腿在后。**顺序错 → 报"时刻倒挂"**。
       **站名与时刻一律从 `--brief` 或 `explore` 写出的 `candidates.json` 里照抄**——实测凭印象写站名（把"乙站→某市"写成"乙某枢纽→某市南"）直接导致一轮返工。
    2. **每条腿都要 `seat`**（票种）：铁路写 `二等座`/`硬座`/`硬卧`，航空写 `经济舱`，接驳写 `地铁`/`打车`。缺了 → `--emit-data` 给不出票种、被生成器的**「价格必须标明票种」**校验拒。
    3. **跨天必须把日期写全**（`"YYYY-MM-DD HH:MM"`）：只写 `HH:MM` 推不出到达日，`rank --arrive-by` 会拒收。
    4. **异站衔接写 `transferMin`**（= 从上一段到站到本段发车所需的接驳分钟数，含出站/转场/进站）：**规范写法是写在后一段上**；写在前一段现在也能认，但**别两处都写**。
       **更稳的做法是直接补一段接驳腿**（既给耗时又给费用，还能显示在页面上）。
    **⚠ 落盘 JSON 一律用 `write` 工具**，不要用 PowerShell here-string / `Set-Content` 写 JSON——那会带上 **UTF-8 BOM**（实测因此多花一次"编码修复"往返；`12306.js` / `plan.js` / `make_html.js` / `itinerary.js` 现在都容忍 BOM，但没必要制造这个问题）。
  - **候选上限 4 个**：每次查询都可能触发 12306 限流（见「数据源 → 12306 限流提示」），**不要为凑候选无限查**。
- **跨天到达标记 `(+1天)`**：脚本按"**到达时刻不晚于发车时刻**"判定 = **车上过夜**。**这是确定性依据**——「普速席别顺序」与「过夜一律标红」都以它为准，不要靠肉眼比对钟点去猜。
- 出发/到达可写**城市名**（自动选主站）或**具体站名**；大都市多站**窗口内无票/无车时再查同城其他站**，方案里说明从哪个站走。

## plan.js 用法（**唯一的方案裁决入口**；完整用法跑 `--help`）

```
node scripts/plan.js <brief.txt> [--at HH:MM | --from HH:MM --to HH:MM] [--pax N] [--json]   # 筛选（= screen，默认模式）
node scripts/plan.js rank <candidates.json>                                                   # 三段归位（--json 仅 screen 模式生效）
node scripts/plan.js candidates <brief.txt> […]                                               # 出候选（不做筛选）
node scripts/plan.js explore --chain "起点,枢纽…,终点" --date 2026-10-01 […]                                                  # 探索（更宽窗口）
node scripts/plan.js compose <腿1.txt> <腿2.txt> […]                                            # 组方案（含分段拼接）
```

- **默认模式**就是**筛选（`screen`）**；正文里出现的 `candidates` / `explore` / `compose` 也都是本脚本的子命令（`--help` 为准）。
- **筛选模式**：把 `--brief` 全谱交给它，**只看它给的短名单**——不要让模型逐条套窗口 / 余票 / 席别规则。
- **归位模式（`rank`）**：三段归位也交给它算（见「方案生成 → 三段归位」），**不要在文字里排**。
- **退出码**：`0` = 窗口内有可用；`2` = 窗口内无可用（**仍会打印窗口外候选**，可作"窗口外最近班次"用）；`1` = 用法或解析错误。
- **口径同源**：本文件「时间窗口规则 / 人数与余票规则 / 席别规则 / 无座票规则」= 脚本的实现依据；**两者冲突时以脚本为准，并把冲突回报给用户**。

## flight.js 用法（**先判成立条件**；完整用法跑 `node scripts/flight.js --help`）

```
node scripts/flight.js route <出发> <到达>      # 有无直飞、承运航司（含中文名）
node scripts/flight.js airport <关键词>         # 查机场
node scripts/flight.js cities                   # 内置中文城市 → 机场对照
```

- **数据边界（必须遵守）**：该库是**社区历史快照**，**不含班期 / 时刻 / 票价 / 余票**，也**不代表该航线目前仍在执飞**。
  - ✅ 只用于**初步判断"该方向有没有直飞"**、避免凭空编造；
  - ❌ **严禁**据它宣称"有航班 / 可以坐飞机过去"——是否仍在执飞、班期与价格**必须用 `web_search` 实时确认**；
  - 实时结果与它冲突 → **以实时结果为准**，按 `references/air-fallback.md` 如实说明。
- 目的地**无机场**（如东莞）会报"无法识别机场"→ 改用**最近机场**（如广州白云/深圳宝安）并在方案里写明**落地机场**；**落地后的市内/城际接驳不在方案内**（一句提示）。
- ⚠ **本库对中国机场覆盖不全——覆盖判据、两种"覆盖不可用"的样子、补救办法与"真结论"反例，一律见 `references/air-fallback.md`「空中数据降级规则」第 1 条（本技能头号红线，只在该处定义，此处不复述）**：命中覆盖不可用（**机场表未收录** / **机场表有但航线表零记录**）时，**不得据此判"无直飞"或"不可达"**，改用 `web_search` 查该方向实时航班（**含中转**）或用机场官网时刻表核对。
- **三字码不再因"库未收录"而报"无法识别机场"**：脚本一律接受三字码；若该地**确实没有机场**，才走上一行"改用最近机场"。
- 数据首次运行自动下载，缓存 30 天（`scripts/.flight_cache/`）。

## map-shot.js 用法（**自驾路线出图唯一入口**；完整用法跑 `node scripts/map-shot.js --help`）

```
node scripts/map-shot.js link <points.json> --out urls.txt   # 出高德链接（网页版 + App scheme）
node scripts/map-shot.js shot "<链接>" <目的地>自驾路线截图.png --wait 24000 --scale 2
node scripts/map-shot.js shot "<链接>" <出图.png> --nodes nodes.json --single   # 带标注 + 只留一条路线
node scripts/map-shot.js shot "<链接>" <节点图.png> --pref 不走高速 --single --nodes nodes.json  # 绕行图：地图自己画地面线
node scripts/map-shot.js shot "<链接>" <探针.png> --js probe.js                 # 注入探测（只读页面状态）
node scripts/map-shot.js selfcheck                           # 不联网自检：坐标转换 + 链接拼装
```

- **`link`**：把**起终点（`vias` 默认留空 ＝ 地图默认最快线，只有客户点名要某条走廊时才填 1 个）**拼成 ① 高德**网页版**链接（免 key、`via[i]` 多途经点；**URL 的 `policy` 参数网页版无效**，别指望它换线）② 高德 **App 唤起**链接（Android `amapuri://` / iOS `iosamap://`，`vian` + `vialons/vialats/vianames` 竖线分隔，`sourceApplication` 必填但**不是 key**）。
- **`shot`**：无头 Edge + CDP：导航 → **等地图渲染完**（默认 24s）→ Esc 关登录浮层（必要时 `--click x,y`）→ 截图。**截图是交付物之一，不是全部**。
- **`shot --nodes <nodes.json>`**：**两种图面模式**（开关写在 JSON 顶层对象）：① **总览图（）**＝`{ "legend": false, "parallel": true, "marks": [ … ] }`，**图上只有「点 ＋ 水平引线 ＋ 名字」**——拥堵段＝主线上的**红点**＋水平引线引出段名（`labelDir:"w"`）、电车充电＝**蓝点**＋水平引线引出服务区名（`labelDir:"e"`），**不出菜单、不写表、不编号、不用线色涂段**；`parallel:true` 会把同侧标注按 y 排成互不重叠的平行阶梯（引线只走水平）。② **节点图**＝默认（带菜单）：**卡点／充电位＝小圆点＋引线＋名字**，说明进菜单。文件顶层也可以是**裸数组**或 **`{ "legendTitle":"菜单：…", "marks":[ … ] }`**。
  - 线（拥堵段）：`{ "type":"line", "level":"high|mid|low"（或 "color":"#C62828"）, "label":"① 古田枢纽（4 次 · 2026 点名）", "weight":10, "opacity":0.72, "points":[[lng,lat],…] }`（`label` 只进菜单）；**地面绕行线不该由我们画**——用 `--pref 不走高速` 让地图自己画（见下），**只在没法让地图画时才**用 `"dash":true` 的绿虚线兜底。`opacity` 让地图自己的线透出来，一眼能看出哪些是标注。
  - 点：`{ "label":"巳市服务区", "legendLabel":"1 巳市服务区 231 km 国家电网", "lng":…, "lat":…, "color":"#0B72C4", "r":7 }`——**`label`＝地图上引线引出的短名**（「拉出一条线引导其服务区名字」），**`legendLabel`＝菜单里的长名**；**点默认不画编号**（客户口径「图上不要编号」）：只有显式写 `number:true` 才贴序号圆点，`parallel:true` 的总览图一律不画；`badge` 只对 `type:"line"` 生效（`badge:true` 才在线上画编号圆点）。
  - `sep` 行：`{ "type":"sep", "label":"沿途充电点（非拥堵路段服务区，间隔 221–275 km）" }`——**只在节点图的菜单里当小标题用**；总览图 `legend:false` 时菜单不建、`sep` 也不画，别加。
  - `legendTitle` 支持内嵌 HTML（用 `<div style="font-weight:400;font-size:11px">…</div>` 加一行小字说明，例如"图上绿线＝地图自己按偏好算的路，报告只加红线标注"）。
  - 画完自动加菜单再截图；**摆位顺序＝（**仅节点图**）菜单先摆、标注后摆**（菜单按四角＋两个底边共 6 个候选位择优，标注候选位多：每个点由近到远试 26/52/86/126/172/224 px × 四方向），所有元素都按**压线几何**打分避让，障碍＝**地图真实折线（AMap overlay 采样）＋ 地图控件矩形 ＋ 左侧路线面板 ＋ 已摆元素**；**先要"四不压"（不压路线 / 不压别的标签 / 不压控件 / 不压面板），找不到才退让，但不许飞到半张图外**。**`shot` 结束会打印 `标注压线 / 标注互压 / 标注退让 / 压线分`——交付前四个数必须全是 0。** **总览图加 `{"legend":false,"parallel":true}` 时不画菜单、引线只走水平、同侧按 y 排成互不重叠的阶梯（点用 `labelDir:"w"|"e"` 指定侧）**；**点必须先投影到路线折线上再写进 JSON**，否则会跑到线外（实测锚点离线最多 9.5 km）；**换走廊后要重跑 `link`**（`_u_*.txt` 是缓存，不重跑会把标注投到旧地图上）。分级与布局口径见 `references/driving-route-planning.md` §8。
  - **菜单末行固定带两句声明**（脚本内置，不用自己写）：「底图与图上实线＝地图自己算路绘制；红／蓝点、引线与名字＝本报告加的标注」＋「**底图上金色／彩色小圆点＝高德自带的设施图标（服务区、加油站等），不是本报告的标注**」。**底图 POI 图标画在 map 的 canvas 上（`--js` 探过：命中只有 `CANVAS.amap-layer`），DOM 删不掉、还会压在我们画的绿线上**——就问过"总览图里为什么有一个黄点"；**只能靠这句声明解释，不要去改图**。 **点用 DOM `AMap.Marker` 渲染**（`content` 放带白边的圆 div）——`AMap.CircleMarker` 在矢量层会被高德地名层压住（实测红点被「申市」「丙市」文字盖掉）。
- **`shot --single`（交付图必加）**：高德网页版默认把 **2–3 条备选路线一起画出来**（左侧面板也列成多张卡片），交付图会"很混乱"（实测被客户打回）。`--single` 只对 `--pick N` 指定那张卡执行点击、把**其余卡片与备选折线隐藏**（拥堵着色线、底衬不动），**它不点「偏好」**——要「不走高速」另加 `--pref 不走高速`（`--pref` 在 `--single` 之前）；要指定"必须是第 N 张卡片"那条就加 **`--pick N`**（N 从 1 数）。**认线看颜色**：选中＝品牌绿 `#00C86E`、备选＝浅绿 `#9ADEC8`——**别按"点数多"认线**（短程路线点数少会认不出，实测节点图那样就漏清理了）。**⚠ 默认选中/首推哪条会随实时路况变**（实测甲市→丙市交付线几十分钟内就掉出前三张卡片）→ 客户指示「默认地图最快线」：**不钉途经点**，先出图、按图上这条线做分析，**一个交付内所有数字取同一次查路读数**并写明读数时间。**只有客户指定走廊时才钉 1 个**（靠终点一侧；实测 1 个与 2 个折线逐点一致），**别钉 2 个**。
- **`shot --pref <文字>`**：点开页面「偏好」并选里面那一条（例：`--pref 不走高速`）→ **地图自己按地面路算路并画线**，我们不用手绘绕行线；在 `--single` **之前**生效，两项一起用。**URL 参数 `policy=3` 实测无效**（网页版照样给高速），要"不走高速"只能走这一项。偏好面板用完会被自动收起（可能留一个折叠触发器，属正常）。
- **`shot --js <inject.js>`**：页面渲染完后注入一段 JS，返回值打印出来（调页面内部状态、做一次性探测用）。
- **`points.json`**：`from`/`to`（`name` + `lng`/`lat`）、`vias[]`（避堵=**地面走廊途经点**（先用「不走高速」模式找走廊，再按走廊上的点加密）、钉两端=**下道口 + 上道口**；**总览图默认留空**，电车充电点改为图上**小蓝点＋引线**标注）、`coord`（`gcj02` 默认 / `wgs84` 自动转）、`policy`（0 推荐 / 1 避拥堵 / 2 避收费 / 3 不走高速）。
- ⚠ **硬性**：途经点 **≤10**（超出**分两条链接**）；**坐标系必须标对**（GCJ-02）；**必须等渲染再截**（load 事件就抓＝白板）；**保留 `© 高德` 版权号、仅供客户本人查看，不得公开再分发或商用**；**里程以图上为准**。
- 前置：**Node ≥ 21**（全局 WebSocket）+ 本机 **Microsoft Edge**；**不需要 key**。完整口径见 `references/driving-route-planning.md` §8。

## congestion-nodes.js 用法（**避堵链 ①②③ 的唯一入口**）

```
node scripts/congestion-nodes.js <route.json> [--date 2026-10-01] [--out nodes.json]
                                 [--top 3] [--max-off 15] [--json] [--debug] [--quiet]
node scripts/congestion-nodes.js --selfcheck        # 不联网：自检地名切分 / 聚类 / 排名
```

- **做什么**：① 取**地图最快路线**当主线（记里程 / 耗时 / 折线）→ ② 把结论库里**被点名**的路段按地名定位（**先用"收费站/互通/服务区"这类高速要素**，裸地名放最后），算它离主线折线多远（默认 **≤15 km ＝压线**）→ ③ **给节点排名**（压线 → 命中次数（年+节假日）→ 最新年份 → 施工/隧道群/枢纽/省界 → 主线先后），排名前 N 标 `needDetail`（要出精细化图）。
- **两个自动防错（实测踩过才加的）**：**① 省别校验**——记录自带 `scope`（某省/某省/…），定位到别省直接丢；**② 路由核对**——锚点自带的道路名（如「某县收费站(**G9106**戌高速出口)」）必须与记录的路名一致，否则判为**平行线**并剔除（实测剔掉了 G9107 巳高速 @230 km、G9108 午高速 @951 km 两条假节点）。跨段记录（A 至 B）**不取中点**，两个锚点各自投影、取离主线最近的那个。
- **输出**：`nodes[]`（排名 / 线上里程 / 离主线 / 命中次数 / 年份 / 依据 / 锚点）、`parallelExcluded[]`（平行线剔除）、`unmatched[]`（定位失败＝**未获取**）。
- **只排名、不打分**：拿不到分段时长数据；评分制（次数 5 / 中位数 5 / 平均 3 / 最长 2，>8 分必须精细化）等有数据再启用。
- ⚠ **`AMAP_KEY` 只从环境变量读**，脚本**不写 key**；**厂商原始响应不落盘**，输出的是我们自己的结论与来源引用。**前置：Node ≥ 18**。
- **直出出图标注**：加 `--marks marks.json` → 每个节点按 `km` 投影到主线上、名字取路段名、红点按严重度分色（`high` #C62828 / `mid` #F4511E / `low` #FF8A80）、`labelDir:"w"` 水平引线、顶层 `legend:false, parallel:true`，**直接喂** `map-shot.js shot … --nodes marks.json`（不用再手工把 `nodes.json` 转成 marks）。
- **严重度由本脚本判定**：带 `--date <出发日>` 时每个节点都输出 `level`（`high` 深红 / `mid` 红 / `low` 浅红）与 `levelWhy`（判定依据）——**出图直接把这个 `level` 喂给 `map-shot.js --nodes`，不要人工上色**。
- 完整链路（节点绕行设计 / 精细化图 / 证据表交付）见 `references/driving-route-planning.md` §6、§8。
- **讲解页的硬性校验在生成时做**：`make_html.js drive <data.json> <out.html> --check` 会先跑 `lib/validate.js`（依据/预案表、未获取、复核清单、严重度、禁用断言）再出页；`check_html.js` 只查通用 HTML 项（A/B/C），**没有 drive 专用规则、也没有 `--kind` 参数**——不要把 `--kind drive` 写进文档或命令行。

## make_html.js drive 用法（**自驾路线讲解页唯一入口**；完整用法跑 `node scripts/make_html.js --help`）

```
node scripts/make_html.js drive <data.json> <out.html> --check
```

- **必须与 `map-shot.js shot` 出的截图成对交付**：截图是"图"，这一页是"文"（图怎么来 / 怎么读、途经点清单、为什么走这条走廊、当天会堵的地方 + 下道绕行 / 错峰预案、电桩计划、时间账、口径与来源）。
- **`sections[type=map].image` 填截图文件路径**：生成器自己读文件、转 base64 **内嵌**（交付物仍是零外链单文件；`check_html.js` 只放行 `data:` 内联图，外链图片照样拦）。
- `waypoints` 第一行是表头；`sections[]` 支持 `map / waypoints / table / grid3 / notes / sources` 六种；`coverCards`、`overview.rows` 与其它页同一口径（同样必需）。
- 页面里**不许出现脚本名 / 接口名 / 数据源名**（A7 会拦）；**官方发布单位、年份、节假日要写**（拥堵数据的底线要求）。

## 其余脚本（同一目录，按需调用）

```
node scripts/traffic-history.js data/high-congestion/segments.json --check     # 结论库体检（字段/年份/来源/窗口）
node scripts/traffic-history.js data/high-congestion/segments.json --match --corridor --top 5
node scripts/traffic-history.js --selfcheck                                   # 解析器自检（不需要数据文件）
node scripts/spots_baseline.js <城市> [--limit N] [--search 关键词] [--json]   # ChinaTravel 基线：该城景点清单
node scripts/spots_check.js <景点数据.json>                                    # 景点页数据校验（数量/热门/开放时间/来源/URL）
node scripts/reply_check.js <回复.txt>                                         # 回复稿门禁（R1≤20 行 / R2 内部用语 / R3 不复述页面）
```

- **`traffic-history.js`**：`--check` 退出码分级（0 合格 / 1 用法错 / 2 数据不合格）；`--match` 按走廊高速编号筛命中，输出「命中明细（年·节假日）」。
- **`spots_baseline.js`**：城市不在基线列表时输出 `CHINATRAVEL=0` 并 **退出码 2**（不是错误，表示改用 web_search）；`--limit` 必须正整数。
- **`spots_check.js`**：景点页生成前跑；拦「<5 或 >10 个景点」「热门 <2」「开放时间写”全天”却没来源」「官方网址不是 http(s)」等。
- **`reply_check.js`**：**发给客户前必须跑**，3 PASS 才能发（脚本名 / 内部用语出现在客户可见文本里会 FAIL）。
