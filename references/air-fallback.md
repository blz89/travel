# 空中兜底（转机方案 · 取数降级）

> 本文件是 `travel` 技能的**参考资料**，由 `SKILL.md` 按需指向。
> **正常流程不要读它**——只有"没有直飞要查中转"或"实时查不到航班号 / 查不到票价"时才读。

## 空中方案的成立条件与定位（先看接驳是否成立，再按三段结构归位；硬性）

最终只输出**最省钱方案 / 最快方案 / 额外方案**三段，交通方式只是实现手段。本节只规定三件事：**空中方案什么时候成立、费用怎么算、算完往哪一段放**。

- **① 成立条件一：去机场必须能"直达机场"**。**只认三种直达方式**——**直达地铁**（城市轨道交通机场线）、**直达动车·城际**（机场联络线直达机场站）、**直达大巴**（机场专线大巴）；不推荐打车（用户主动问时才作兜底提及）。分两种情形：
  - **本地有机场**：出发地 → 机场，上述三种直达方式**至少有其一**；同时存在多种时**全部列出并比较**（耗时 + 票价），供用户选择。
  - **本地没有机场（或本地机场没有合适航班）**：**先坐铁路/动车/高铁到机场所在城市的市区站**（这一段按正常城际段写车次号），**再从该市区站坐"直达机场"的线路进机场**——仍只认上列三种直达方式，**"市区站 → 机场"这一段必须是直达**（无需换乘）。
  - 三种直达方式**一条都用不上**（或"市区站 → 机场"只能靠两次以上换乘）→ **该地不走航空、不列空中方案**，并在聊天回复里如实说明原因（如"无直达接驳：地铁/动车/大巴均需换乘，故不推荐空中"）。
  - **接驳基准 = 你最终选定的那个航班所在的机场**：先定航班（在哪个机场起降），再按**该机场**查"出发地 / 市区站 → 机场"的直达线与票价；同城多个机场时**只算你选中航班所在的那个机场**，不预先挑机场。
- **② 成立条件二：必须能给出航班号**（每一段都要）。拿不到具体航班号 → **直接放弃该空中方案**，**不得**编造，**不得**用"以购票平台为准"凑数。
- **③ 费用必须报全（不得只报机票裸价）**：按「方案生成 → 所有方案通用」的费用口径**逐项列出**，不得合并成"机票 ¥X"。其中：**机场建设费**国内一般 ¥50/人（部分支线 ¥10 或免征），**燃油附加费**参考 ¥20–70/人，均以出票页为准；**出发端接驳费**含"市区站 → 机场"那一程。例：「经济舱票价 ¥600 + 机建 ¥50 + 燃油 ¥40 + 接驳 ¥25 ≈ **¥715/人**」。
- **④ 定位规则**：把全部候选（铁路各方案 + 空中各形态）按**同一口径**算出**总耗时**与**总费用**后直接归位——
  - **算完往哪一段放**：一律按「方案生成」的三段定义归位（最省钱 / 最快 / 额外），**本节不另立口径**。
  - **空中方案通常就是最快方案**；**若最快的是铁路（通常说明出发地/目的地较近、航空没优势），那最快方案就是铁路，空中方案自然不进主方案**——这种情形下它也大概率不进额外方案，**直接不列空中方案**，一句话交代原因即可（如"空中约 7.5 小时，不快于铁路 5.5 小时，故不列空中方案"）。
  - **仅当用户明确要求"看看飞机"**时，才把未入选的空中方案如实给出（**未入选者一律不进三段、不进网页，已查到的航班号也无需在聊天里列出**），并显著标注"总耗时更长 / 总价更高，不推荐"。
  - **算账口径统一**（唯一权威定义见「方案生成 → 所有方案通用」）。机场或车站离市区较远时，在聊天回复里**一句提示**即可（不进方案、不计费）。

## 转机与空中取数兜底（无直飞必查；查不到时如实说明）

**没有直飞不得直接判"空中不可行"**——必须查**中转航班**（按飞猪 / 携程 / 去哪儿给出的中转组合执行，不自创拼接）。
`flight.js` 只是历史快照，**拿不到航班号才放弃该空中方案；查不到票价不放弃**——**有航班号但取不到当日票价时，改用最近可查的参考价，并显著标注"非当日实价，以出票页为准"**（如"经济舱参考价 ¥900/人（**含机建 + 燃油**，9 月价，非 10-01 实价）"）；**票价处理（2026-10-07 定）**：**有参考价（有数字，含机建 + 燃油）→ 照常参与「最省钱」比价**（把它写成数字进该段 `legs[].cost`，页面标注"参考价、非当日实价、以出票页为准"），**也照常参与「最快」**；**只有"参考价待定"（无数字）→ 才不参与「最省钱」**——**唯一例外**：到达日内它是唯一候选（或全部候选都没数字）时，**必须照给「最省钱」**（见 SKILL.md「1. 最省钱」）。
转机的时间校验、必须呈现的信息，以及空中取数的降级顺序，见下面两节（都在本文件内）。


## 转机（中转航班）方案规则（无直飞时必查；**照飞猪/携程等购票软件的中转组合执行**）

- **为什么需要**：很多航线**没有直飞**（尤其出发地/目的地是小机场）。此时**不得直接判"空中不可行"**，必须查**中转航班**——**按飞猪 / 携程 / 去哪儿给出的中转组合执行**（购票软件给出的中转方案一般可行）；**多段拼接、跨航司自行发明的中转不要做**。
- **触发条件**（满足任一即查中转）：① `flight.js route` 显示**无直飞**；② 有直飞但**时刻不合适 / 价格明显偏高**；③ 出发地或目的地**没有机场**（那就要先接驳到最近机场，再走直飞或中转）。
- **前提（硬性）**：
  - **必须比直飞便宜才考虑**（**只适用于触发条件②里"价格明显偏高"这一种情形**）——因价格而考虑转机时，转机价**不便宜于同航线直飞**就直接用直飞，不给转机方案；**直飞时刻不合适 / 无直飞 / 没有机场这三种情形不受本条限制**（那时本来就没有可用的直飞）；
  - **只取平台的现成组合**（飞猪 / 携程 / 去哪儿那种一次出票、行李直挂的联程）：**多段拼接、跨航司自行发明的中转不做**；**需要换机场的（某枢纽→某机场等）可以做**，按下面「非同机场」那一条单独校验。
- **必须呈现的信息（照购票软件口径）**：**中转机场**（如"经上海虹桥"）、**中转等待时长**（如"中转 2 小时 10 分"）、**每段航班号与时刻**、**总耗时**（首段起飞到末段落地，含中转等待）、**总价**；并注明**是否同一航司（行李能否直挂）、是否需要重新值机**（**非同机场转机**要写清机场间转场方式与耗时）。
- **中转时间校验（硬性；2026-10-07 收束）**：
  - **平台给出的转机组合 → 不做任何时间校验**：飞猪 / 携程 / 去哪儿给的转机**基本必然是同机场**（同航站楼内换乘、一次出票、行李直挂），衔接由航司安排并担保，赶不上由航司改签；**跨航司联程同样豁免**（联程与航司品牌无关）。在候选或该段上写 `throughCheckin: true` 留痕即可——**漏标不拦，只提示**。
  - **非同机场转机极罕见**（虹桥→浦东这类，平台基本不提供、旅客要自己转场）→ **先尽量换平台方案**；确实只能这样走时，唯一规则 = **必须在下一段航班起飞前 1.5 小时（90 分）到达下一段所在机场**（含机场间转场耗时），并在**后一段写 `transferMin` = 机场间转场分钟数**（缺了会被判"数据不全"）。**不再用"≥2 小时 30 分"这类自设门槛。**
  - **地面腿 → 航班**（如机场快线 / 地铁 → 航班）→ **要留 ≥90 分**（= 起飞前 1.5 小时到达机场，值机 / 安检缓冲）。
  - **不自行拼段**：要用转机就走平台给出的现成组合；平台给不出、要自己拼两段票的组合**不要做**。
  - **不要替航司复核平台的联程**：平台在售的整票中转，衔接责任由承运方承担——**我们只采信，不另设分钟级门槛**（也不为"凑一个符合自设门槛的组合"再去搜索）。
- **定位**：中转方案的总耗时与总价按同一口径计算，参与「最省钱 / 最快 / 额外」三段归位（见「空中方案的成立条件与定位」）；归不进任何一段就**不列**。
- **代号不省略**：中转方案的**每一段都要写航班号**；**给不出航班号的转机方案直接放弃、不上页**（不得编造）。

## 空中数据降级规则（查不到时如实说明，禁止编造）

按以下顺序取数，**每一步都不得虚构航班号、时刻或票价**：
0. **先看成立条件**：按上文「空中方案的成立条件与定位」检查两条硬条件——① 去机场能否**直达机场**（本地无机场时：先铁路到市区站，再由市区站直达机场）；② 能否拿到**航班号**。任一不成立 → **不列空中方案、也不必再查航班**，一句话说明原因即可（用户明确要求"看看飞机"时除外）。
1. **再判航线**：`flight.js route` **初步**判断有无直飞与承运航司——**若无直飞，不要直接放弃**：**先读脚本的"覆盖不可用"警告**（见下条），确认这次结论能不能用；再按「转机（中转航班）方案规则」查**中转航班**；**该库为历史快照，判出"有直飞"也不得直接采用**，必须经下一步实时确认（是否仍在执飞、有无班次）。
   - ⚠ **判据是"本库有没有该机场的航线记录"，不是"有没有机场"**：脚本会**显式点名**本次用到的、本库覆盖不可用的机场——① **机场表未收录**（如成都天府 **TFU**）；② **机场表有、但航线表里零记录**（如北京大兴 **PKX**——2019 年启用，本库航线停在 2014 年）。
   - 命中任一 → **本次"无直飞"结论不可用**，**不得据此放弃空中方案**；必须改用 `web_search` 查该方向实时航班（**含中转**）或用机场官网时刻表核对。
   - **多机场城市逐个机场核**：北京 **PEK/PKX**、上海 **SHA/PVG**、成都 **CTU/TFU**——本库常只收录其中一个，只看收录的那个会漏掉真实存在的直飞。
   - **只有"两边机场在库里都有航线记录、但这两地之间查不到"才是真结论**（该方向本就无直飞，需中转）；**脚本原先说"目的地没机场"的那种情形（如东莞），改用最近机场**。
2. **再查班期与参考价**：`web_search`"城市A 到 城市B 航班 时刻 机票"——**必须查到具体航班号才算数**；只拿到"每天 X 班、参考价 ¥X 起"这类**没有航班号**的信息时，按第 3 条放弃该空中方案（不得只凭"每天 X 班"就当成一个方案写出去）。
3. **拿不到具体航班号/班次 → 该空中方案直接放弃、不列入方案矩阵**（硬性）：只在聊天回复里如实说明"该方向有航线，但实时查不到具体班次/航班号，故本次不列空中方案；如需可自行在购票平台查询"，并提示"铁路方案更确定，可优先考虑"。**不得**编造航班号/时刻/票价，**不得**用"约 ¥XXX"或"以购票平台为准"凑一个方案出来。**本条只管"拿不到航班号/班次"这一种情形；"查不到票价"怎么办，见下一条。**
4. **只有"拿不到航班号"才放弃；"查不到票价"不放弃（硬性）**：若已查到**航班号 + 时刻**、只是查不到当日票价，**仍必须把空中方案分析出来并列出**——写全**航班号、时刻、接驳方式与耗时、总耗时**；**票价栏优先给数字**：写"参考价 ¥X（**含机建 ¥50 + 燃油 ¥Y**，查于 <日期>，非当日实价、以出票页为准）"——**只要能查到同航线参考价就给数字（票面 + 机建 + 燃油的可比总价）并标注**；确实一个数字都没有时才写"票价以出票页为准"。（机场建设费 / 燃油附加费 / 出发端接驳费按「费用必须报全」逐项列出，均为参考值。）**不得编造票价数字**，也**不得**因为"没查到票价"就把整条空中方案丢掉——**客户要的是"飞机路线也要分析"**。**票价处理（2026-10-07 定）**：**有参考价（有数字）→ 把"票面 + 机建 + 燃油"写成该段 `legs[].cost` 的数字，照常参与"最省钱"比价**（页面标注"参考价、非当日实价、以出票页为准"），也照常参与"最快"；**只有确实没数字（`cost: null`）→ 才不参与"最省钱"归位**（费用不可比），但照常参与"最快"；**若它在到达日内是唯一候选（或全部候选都没数字），它就是最省钱方案、本段必须照给**（口径见 SKILL.md「方案生成 → 1. 最省钱」）。
