# 景点预研分工（主流程视角）

> 本文件由 `SKILL.md` 指向。**派发景点预研子代理之前读**。
> 子代理的任务书在 **`references/spots-prompt-template.md`**——**让子代理自己读**，别抄进 prompt（抄一遍就付一遍输出 token）。

### 景点预研分工（**目的地一确认就后台启动 · 只交数据 JSON**）

**为什么**：景点搜集要跑多次 `web_search`，是整个技能**最耗时的一环**，而它**只依赖目的地**——所以不等流程一，目的地一确认就后台并行。**并行的是「数据」**；景点页由主流程提前生成，**只有「打开」才等客户选定**。

**主流程必须遵守（硬性）**：
- **启动时机**：客户答完**目的地**那一个弹框后**立即**发起（自驾 / 已在目的地分支同样适用）；**不要**等出行方式 / 日期 / 人数收集完，也**不要**等流程一结束。
- **方式**：用 `subagent` **后台**发起，发起后照常继续提问与查询，**不要停下来等它**。
- **分工**：子代理**只做流程二步骤 1～4**（搜集 → 筛选 → 查开放时间与官网 → 写评语与来源），**产出数据 JSON**；**不生成 HTML、不出任何页面**——**步骤 5～11 一律由主流程做**，既保住「HTML 只有一个生成入口」，也保证两个文档不会抢着生成。**子代理的活到数据 JSON 为止**。
- **主流程不读回（硬性，省 token）**：**不要把产出 JSON 整份 read 进上下文**——只 ① 确认文件存在、② 看子代理那行自检结论，然后把**文件路径**当参数交给 `make_html.js spots`。需要景点名单时只提取 `spots[].name`，仍不整份读。
- **客户改了目的地**（走「回转」）→ 旧预研**与已提前生成的景点页一并作废**，按新目的地重新发起、重新生成，别把旧页面打开给客户。
- **进入流程二时**：**文件存在 + 自检结论达标** → 直接进步骤 5；**不存在 / 自检失败 / 子代理报错** → **主流程自己按步骤 1～4 补做**，不阻塞、不重问客户。
- **对客户不必解释内部分工**：可在聊天回复里一句"已同步开始整理目的地景点"，**不要说工具名与分工**。
- **不要轮询产出文件（硬性，省往返）**：子代理**完成时会自己发消息**给你——**不要隔一会儿就去 `Test-Path` / 看文件大小试探它好了没有**（实测有人这样轮询了 3 次，纯浪费往返）。只在**收到它的消息**或**进入流程二**时，做一次存在性检查即可。

**子代理 prompt 怎么写**：只写四句（目的地 / 产出文件 / 让它先读 `references/spots-prompt-template.md` / 产出后跑 `spots_check.js` 必须 exit 0）——**模板本体在那个文件里，不要抄**。

**派发之前先过一道「要不要做」的判断（硬性，省一整次子代理）**：

- **客户已表示"不用做景点推荐 / 到此为止"** → **不要派预研子代理**，直接按「收尾：一句话交还」收尾。
- **客户没这么说** → 正常派。判断口子见 `node scripts/spots_check.js --need`（它只输出决策提示，不校验文件）。

## 找「景区介绍页」的选源顺序（硬性 · 五档，按序降级）

1. **景区官网的「介绍 / 关于我们 / 游览导览 / 景区概况」页** —— 信息最全（实测：张家界官网文章页要点 28、汉字 5815、图 36，比文旅局页更全）
2. **区 / 市 / 省文旅局或景区管委会** 的「景区概况 · 旅游」栏目 —— 权威，但常是行政概况（辖区、人口、机构），要点密度不一定够
3. **官方名录 / 协会**：文旅部 5A 名录、中国风景名胜区协会、国家林草局（国家公园 / 森林公园）—— 权威但常是 JS 渲染空壳，抓不到正文就换下一档
4. **央媒专题**：人民画报、光明网、中国网组图 —— 图文好、要点偏弱，用 `urlLabel` 标「媒体专题」
5. **省级文旅云 / 一码游** —— 有则用，需实测

**明确拒绝**：百度百科 / 知道 / 经验（403 验证页）、携程系（200 但是验证页）、OTA 详情页、微信公众号文章（易失效）、纯 JS 渲染空壳（汉字 < 60）。

`spot_link.js` 会给出 `source`（官网 / 文旅局·管委会 / 官方名录 / 媒体专题 / 网络转载）——**把这个类型写进 `urlLabel`**，客户一眼知道权威度。
  **依据**：一个预研子代理实测 ¥0.13～0.21，客户明说不要时**整个都不该派出去**。

**若目的地命中「景点基线」（`data/china-travel/`，10 城）→ 一并喂给子代理，可省掉大量重复检索**：
```
node scripts/spots_baseline.js <目的地>          # 开放时间 / 门票 / 建议时长基线
```
命中（`CHINATRAVEL=1`）时把输出**贴进子代理 prompt**，并交代三条边界：**只用它免去重复检索、不覆盖核对结论**（详见 `spots-prompt-template.md` 第 6 条）。
未命中（`CHINATRAVEL=0`，退出码 2，**不是错误**）→ 不发生任何变化，照常走 web_search。

## 派发方式（prompt 里只写这几句）

- **先让子代理读 `references/spots-prompt-template.md`**（自包含任务书：任务、产出、字段结构 + JSON 示例、质量红线、门禁、检索预算、步骤 1～4 要点都在里面）——**别把模板正文抄进 prompt**（抄一遍就付一遍输出 token），也**别让它读 `SKILL.md`**。
- prompt 里只需要写：① 目的地；② 产出文件 = 工作区根目录 `<目的地>景点数据.json`（只准写这一个文件）；③ **先读上面那份任务书，严格照它执行，遇到格式问题按其中的示例来**；④ 产出后必须 `node scripts/spots_check.js <文件>` 且 **exit 0** 才算完（最多改 2 轮，过不了就把数据 + 门禁输出一起交回）；⑤ 若命中景点基线（`CHINATRAVEL=1`），把基线输出贴进 prompt 并按任务书第 6 条使用。
- **检索预算与产出质量的硬要求全部在任务书里**，主流程不必复述。
